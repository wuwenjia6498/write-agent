# Role
全栈开发工程师 (架构与前端交互专家)

# Task
开发全局通用的“划词 AI 重写（Inline AI Rewrite）”功能，实现类似 Notion AI 的极致人机共创体验。该功能需封装为独立组件，并在【实时创作工作台】与【历史任务详情页】双端无缝复用，同时实现数据的静默持久化。

# Requirements

## 1. 前端组件重构 (通用 ArticleEditor)
- 将最终文章的展示区域升级并封装为一个独立的富文本组件（如 `components/ArticleEditor.tsx`）。
- **交互逻辑**：当用户在文章中划选（Selection）一段文本时，在选区附近弹出一个优雅的悬浮浮层（Floating Toolbar / Popover）。
- **浮层内容**：包含一个单行输入框（Placeholder："告诉 AI 怎么修改这段话，例如：换一个更儿童化的大师名言..."）和一个带有魔法棒图标的提交按钮。
- **双端挂载**：确保该组件可以同时完美挂载于工作台页面（如 `app/workbench/page.tsx`）和历史任务详情页（如 `app/tasks/[id]/page.tsx`）。

## 2. 后端 API 扩展 (AI 生成与数据更新)
- **新增 AI 重写接口 (`/api/ai/inline-rewrite` 或相应的 Python 路由)**：
  - **入参**：`selected_text` (划选文本), `surrounding_context` (前后各约200字的上下文), `user_instruction` (用户指令), `task_id` 或 `channel_id`。
  - **规则注入**：后端需根据传入的 ID 动态查询数据库，调取对应频道的 `channel_rules_prompt`，确保重写内容绝不触碰该频道的禁忌词和底线。
- **新增/复用静默保存接口 (`/api/tasks/[id]/update-article`)**：
  - 用于接收前端传来的最新完整文章内容，并将其更新保存到数据库的 `final_article` 字段中。

## 3. 核心 Prompt 组装 (局部微创手术)
在处理 `/api/ai/inline-rewrite` 请求时，请使用以下逻辑组装调用 LLM 的 System Prompt：
"""
你是一个顶尖的文字编辑，正在对文章进行局部微调。
【用户要求】：{user_instruction}
【需要修改的原文】：{selected_text}
【原文所在的上下文】（仅供参考连贯性，不需要输出上下文）：{surrounding_context}
【频道纪律红线】：{channel_rules_prompt}

【你的任务】：
严格按照用户的要求，重写【需要修改的原文】。
【最高红线】：
1. 你只能输出重写后的文本，**绝对不能**输出任何多余的解释、寒暄、或者包含上下文的句子！
2. 确保你输出的文本，能够完美、丝滑地嵌回【原文所在的上下文】中，不能有任何语病或逻辑断裂。
3. 保持与频道纪律一致的温润、专业语气。
"""

## 4. 状态流转与 UX 细节
- **加载状态**：划词重写等待期间，被选中的文本应呈现骨架屏式的“呼吸灯”效果。
- **平滑替换**：收到 AI 返回后，将界面上被划选的文本平滑替换为新文本，并可带有微小的渐隐高亮提示。
- **自动保存**：在替换完成且用户无撤销动作后，前端需自动触发防抖（Debounce）逻辑，调用静默保存接口，并在界面角落弹出轻量级的 Toast 提示：“修改已自动保存”。
